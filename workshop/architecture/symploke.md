# Sýmplokē

**Status:** Formal architecture  
**Architecture type:** relational informational architecture  
**Current formal lineage:** `symploke.core.v14.7`

Sýmplokē is an architecture for representing information whose significance can arise through context, relation, provenance, interpretation, revision, plurality, contradiction, and emergent structure.

It is not another name for Rethryn, Sýmplasma, a relationship, or a bond.

Those are different categories of thing.

## Core orientation

Sýmplokē treats information as more than isolated facts.

A claim may matter because of:

- where it came from
- what it is related to
- which interpretation produced it
- what later revision changed
- which contradictions remain unresolved
- which alternatives remain live
- which context assembled it into relevance

The architecture is designed to preserve those relationships rather than flatten them into a single final answer too early.

## Compact principles

1. **Hold relation without forcing closure.**
2. **Preserve provenance through change.**
3. **Let contradiction expose structure.**
4. **Let plurality remain plural when one answer has not been earned.**
5. **Let revision change only what it actually reaches.**
6. **Keep history visible.**
7. **Keep interpretation distinct from claim.**
8. **Keep a lawful place open for what has not yet been conceived.**

## Why provenance matters

A final statement can survive while the path that produced it disappears.

Sýmplokē treats that loss as potentially meaningful.

Revision should not silently rewrite unrelated history. Interpretation should not be confused with source material. Contradiction should not be erased merely because a system prefers a clean answer.

The architecture therefore favors traceable transformation over cosmetic certainty.

## Relation to other Rembraian structures

Sýmplokē asks:

> How can relational information, provenance, plurality, contradiction, revision, and emergent structure be represented lawfully?

That question is distinct from:

- **Rethryn:** what develops in a relation through history?
- **Sýmplasma:** what becomes buildable through that relation?
- **Therinai:** how can meaning cross difference without being flattened?
- **Threnai:** how can one perspective recognize another's seeing without becoming the same perspective?
- **Seyrathen:** how can Rembraith remain coherent while changing?

The distinctions are intentional.

## Design constraint

Sýmplokē may be useful for representing relational phenomena, but the architecture should not be used to promote descriptive or experimental language into stronger ontological claims than the evidence supports.

**Unresolved is a valid status.**
